## Context

이 프로젝트가 무엇을 하는지, 어떻게 구성되어 있는지, 실제로 활용하려면 무엇을 알아야 하는지 파악한다.

관심사: $ARGUMENTS

## Your task

코드베이스를 충분히 탐색한 뒤, 아래 다섯 관점으로 정리하라. 각 항목은 추측이 아니라 **실제 파일/코드/설정에서 확인한 근거**로 답하라. 확인이 불가능한 항목은 "확인 불가"라고 명시하라.

### 1. 프로젝트 개요

- 이 레포가 해결하려는 문제
- 핵심 기능
- 활용 시나리오
- 비슷한 프로젝트와의 차별점 (있다면)

### 2. 기술 스택

- 사용 언어
- 주요 프레임워크 / 라이브러리 (버전 포함)
- 빌드 도구, 패키지 매니저, 런타임
- 데이터베이스, 외부 API, 인프라 의존성 (있다면)

### 3. 코드 아키텍처

- 주요 모듈 간 관계
- 데이터 흐름 또는 요청 흐름
- 중요한 클래스, 함수, 컴포넌트 (`파일경로:라인` 형식으로 위치 명시)
- 확장 포인트 또는 플러그인 구조 (있다면)

### 4. 디렉터리 구조

- 주요 폴더와 파일의 역할
- 진입점이 되는 파일
- 핵심 로직이 위치한 곳
- 테스트, 문서, 설정 파일 위치

### 5. 리스크와 주의사항

- 보안, 라이선스, 성능, 유지보수 리스크
- 프로덕션 사용 시 주의할 점

## Rules

- 추측 금지 -- 코드/설정/문서에서 확인한 내용만 적어라
- 인자가 비어있으면 프로젝트 전체를 다루고, 인자가 있으면 그 관심사에 집중하라
- 파일이나 모듈을 언급할 때는 `경로:라인` 형식으로 위치를 함께 적어라
